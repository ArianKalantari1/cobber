## What was shipped this session

### 1. Culinary affinities layer — fully wired

A new scoring stream: what food chefs pair (distinct from cocktail history
and craft bartenders, which are already separate streams).

- **Data:** `data/culinary_pairs.json` — 105 pairs, currently PROVISIONAL
  (model-estimate scores, not yet expert-grounded). Works today; needs the
  reference-and-curate step below to replace the estimates with real data.
- **Engine:** `engine.culinary_affinities(ingredient_id, n)` — looks up the
  table, enriches hits with shared aroma compounds + harmony score where the
  chemistry confirms the pairing.
- **MCP tool:** `get_culinary_affinities(ingredient_id, n=10)` — the host
  Claude calls this when building a culinary-crossover or novel cocktail.
  Returns pairings sorted by affinity, with cuisine contexts and a note on
  whether the pairing is compound-confirmed or purely chef-empirical.
- **Tests:** 88 total, all passing. Validator hardens the data file against
  duplicate pairs, unknown ingredients, and out-of-range scores.

### 2. Source evaluation — brege/the-flavor-network (The Flavor Bible)

A hands-on evaluation of the best available expert culinary-pairing dataset,
documented in `docs/culinary-source-evaluation.md`. Key findings:

- 25,684 expert pairings extracted from *The Flavor Bible* (Page & Dornenburg
  2008), with 4-tier emphasis weights validated against the book's typography.
- Weight 4 = "Holy Grail" pairing (e.g. apple + cinnamon). Only 45 pairs at
  this tier across 1,375 ingredients — rare and meaningful.
- Coverage: 65 of Cobber's 96 ingredient ids map to a Flavor Bible node.
  **All 15 Australian natives are absent** — the book is a US food book.
- Copyright blocker: the MIT licence on the GitHub repo covers Wyatt Brege's
  code, not Page & Dornenburg's creative content. Bulk-committing the pair
  matrix would be legally infringing.
- **Ari's decision:** reference-and-curate — use it privately at build time
  as a seed and sanity-check; Ari approves every pair before it goes in;
  no book matrix committed to this repo.
- The evaluation also caught that several of the model-estimate scores in the
  current `culinary_pairs.json` were overconfident. Example: `strawberry +
  basil` (scored 0.82 by the model) is entirely absent from the Flavor Bible
  expert data. `peach + almond` (scored 0.85) is only a weight-1 standard
  mention. The PROVISIONAL label is justified.

### 3. Reference-and-curate pipeline

`scripts/build_culinary_pairs.py` — run this any time to generate a draft:

```
python3 scripts/build_culinary_pairs.py
```

It downloads the Flavor Bible network from GitHub (not committed — copyright),
maps Cobber ingredient ids to Flavor Bible nodes via a hand-verified alias
table, and writes `data/culinary_draft.json` (gitignored). Draft results:

| Flavor Bible tier | Pairs |
|---|---|
| Weight 4 — Holy Grail | 2 |
| Weight 3 — Highly recommended | 32 |
| Weight 2 — Recommended | 140 |
| Weight 1 — Standard mention | 409 |
| **Total** | **584** |

Each draft pair has `fb_weight`, `affinity_score = weight/4`, the original
Flavor Bible node names for traceability, and `ari_approved: null`.

### Priority 3 — Name the 12 proportion templates

**What:** `data/proportion_templates.json` has 12 templates with placeholder
names like "Spirit-Forward Build" and "Sour Template". These come from
k-means clustering of 8,416 real recipes — the centroids are real, the
names are descriptive stand-ins.

Each template has:
- `suggested_name` — the placeholder
- `benchmark_drinks` — real drinks that land in this cluster
- `centroid` — the actual proportion fractions (e.g. spirit 0.48, acid 0.21,
  sweet 0.16...)

**What to do:** Read the benchmark drinks for each template and give it a
name you'd actually use ("Sour", "Old Fashioned Build", "Negroni",
"Highball", "Flip", etc.). You don't have to rename all 12 at once.

**Why it matters:** Until renamed, the server INSTRUCTIONS tell the host
to avoid using the template name and use structural descriptions instead
("a Sour-style build"). Naming them makes Cobber's output cleaner and
more direct.
